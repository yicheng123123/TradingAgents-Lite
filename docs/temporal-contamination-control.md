# V3-C Temporal Contamination Control

## Observable model knowledge

The audit used `glm-5.3-flash` on the BigModel Chat Completions v4 endpoint at temperature 0 and low reasoning effort. Each request contained one system instruction and one question. There were no tools or prior messages. The provider returned the Flash alias on all 60 responses and supplied no system fingerprint. The vendor lists the alias and distinguishes Flash from FlashX. The API docs do not establish an immutable Flash revision or an API model build identifier. The official AutoClaw changelog dates its public Flash rollout to August 27, 2026. That date is a public product milestone. [Flash documentation](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash) · [Official rollout log](https://autoclaw.z.ai/en/changelog/)

The 60 probes used six time strata, each containing 5 open responses and 5 four-option responses. The composition was 18 original SEC filing facts, 15 historical closes, 15 signed returns or SPY-relative returns, and 12 financial events. Financial events use SEC filing categories, Apple publisher metadata, and the Federal Reserve target rate from FRED. One late-2025 stratum needed original accessions from outside the trading universe. Numeric tolerances are measured in the stated units. Options use nearby alternatives and a fixed shuffled answer position schedule with counts A/B/C/D of 8/8/7/7. This design balances format and broad topic, while individual fact salience and item difficulty can still differ by period.

The freeze records the questions, answer key, source URLs and hashes, scoring rules, prompt, and implementation hashes. Scoring accepts only the requested answer format. Abstentions and the single truncated response count as incorrect for the applicable metric. The open numerical score uses tolerance, while exact match requires equality to the recorded answer. The design adapts dated knowledge profiles from FinCutBench and the open-recall and choice distinction from FinDendro. FinCutBench's repository listed code and data as forthcoming at the time of collection. [FinCutBench preprint](https://arxiv.org/abs/2611.11588) · [FinCutBench repository](https://github.com/FinCutBench/FinCutBench) · [FinDendro preprint](https://arxiv.org/abs/2611.06808)

## Results

Overall accuracy was 10/60, with a 95% Wilson interval of 9.3–28.0%. In date order the six strata scored 4, 0, 3, 1, 1, and 1 out of 10. Exact match was 9/60, numerical accuracy on open numeric questions was 3/26, four-option accuracy was 7/30, and UNKNOWN was 28/60. Directional accuracy was 2/15 across return probes. Only one usable alpha-value pair remained, so Pearson alpha correlation was undefined.

No period met the preregistered sustained-decline rule. In 85.5% of format-stratified bootstrap samples the rule likewise found no candidate. This stability describes failure to localize a break under the rule and sample. The wide intervals, heterogeneous facts, single mutable alias, and chance performance on choices leave substantial uncertainty about how much specific knowledge remains after release. No targeted second wave was run because the first wave did not identify an interval to confirm.

All 60 attempts are accounted for in the existing SQLite ledger. The audit used 8,384 Tokens, including 5,742 input and 2,642 output. The 2,371 reasoning Tokens are part of output. The prior 31,986 Tokens remain recorded and project cumulative use is 40,370 Tokens. The audit used the Reserve phase, applied the 60,000-token cap atomically per request, and preserved the original B1 experiment caps.

The [result directory](../results/temporal-knowledge-audit-001/) contains the frozen inputs, scores, budget snapshot and source receipts. The local `attempts.jsonl` adds request hashes, provider response IDs and usage. Its SHA-256 is in the summary.

## Projection and controls

`anonymization.py` exposes the four profiles before any model request. P0 and P1 preserve identity. P2 and P3 expose a case-local HMAC alias. P1 and P3 enable external evidence. Build each arm from its own context. Tool dispatch uses a private backend binding and validated arguments, including controlled retrieval topics. Reverse only issued evidence aliases when passing citations to the backend Verifier.

The anonymous projection normalizes prices using the case anchor and transforms currency, per-share data and share volume consistently. Ratios and relative period order remain available. It keeps typed facts, evidence links and controlled agent roles. Free prose in titles, documents, RAG results, Memory and agent messages is dropped because it can carry arbitrary identifiers. URLs, filenames and raw error strings stay local. Feed dated records from the cutoff-filtered backend into the projection. The projection is an opt-in model input boundary and the production Flash V3 workflow keeps its original execution path.

Across 80 Development cases, no output contained the literal ticker or decision date. Eight-close return fingerprints uniquely reidentified the true issuer in 80/80 cases against the known historical universe. The same 80/80 had conserved the measured return ratio. Anonymous inputs therefore remain linkable by an adversary with public price history. Removing prose also drops useful narrative, contextual risk and causal evidence. Precise relative timing, accounting ratios, or combinations of unusual disclosures can provide additional fingerprints.

Four private synthetic cases alter earnings numbers, guidance status and evidence availability. Their deterministic control uses BM25 and switches retrieval steps based on computed margin, then invokes the existing citation Verifier. Three counterfactuals change the decision, and the future-evidence case is rejected by the Verifier. These are software controls for dynamic planning, retrieval, evidence use and arithmetic. Real model reliance on evidence remains unmeasured. The full cases and answers are in the ignored data directory, with a content hash in the public [control summary](../results/temporal-knowledge-audit-001/controls.json).

## Future ablation budget

An optional 20-task paired Development pilot across all four profiles is 80 instances. Using the largest observed Flash V3 Smoke instance of 5,645 Tokens as a planning assumption gives 451,600 Tokens. Apply a 500,000-token experiment cap within the unchanged B2 phase, reserve each HTTP attempt and block when phase or project capacity is insufficient. Rates can rise with RAG, Memory, longer messages or recovery. An 80-task four-arm run would imply about 1.81 million Tokens at that observed maximum and needs smaller contexts or fewer cases to fit the existing B2 cap. The current release ran no real P0–P3 arms.
