# A3 多 Agent 与条件辩论

Runner 创建截至当前任务 cutoff 的 MarketView，图退出后才读取结算窗口。图内路径为 prepare → analyst ↔ tools → route → bull / bear → adjudicate → trader → verifier → risk。附加节点由 A3Config 控制，独立 B1 入口沿用原来的图。

Analyst 的 MarketReport 引用本轮工具消息。Bull 和 Bear 分别收到同一份精简报告和引用证据，补充轮使用上一轮的同一快照。ResearchView 和 Claim 区分事实、推断和不确定性，并要求每条论点携带证据 ID。Trader 接收结构化观点、当前证据和独立字段中的历史经验。Risk Manager 仍用确定性波动门。

- D0 跳过辩论，D1 固定运行一对角色。
- D2 依据证据稀少、接近动量阈值或波动风险触发，并检查剩余额度。
- 补充讨论需要显式启用、双方行动冲突、引用集合不同、额度充足。最多生成两对角色。
- 双方独立组织论点有助于暴露证据缺口。共用有偏证据或模型时，额外角色可能重复相同错误。这里只将可解释指标用于路由。

A3 的单次提示上限为 12,000 字节，输出上限为 512 tokens。业务修复与角色请求都经过 ModelBackend._call 的 SQLite 原子预留。离线统计记录 UTF-8 序列化上下文长度，并单列 Mock 用量。

## 面试问题

1. 为什么 Runner 在图退出后才读取结算数据？
2. 为什么 Bull 和 Bear 获得同一个证据子集？
3. 补充轮为什么要保存上一轮的快照？
4. 触发条件与语义可信度有什么不同？
5. D2 的预算检查给哪些节点留余量？
6. 图步数上限和 Token 上限约束哪些不同的风险？
7. 为什么历史经验应该与当前事实分字段？
8. 哪些轨迹能证明 D2 降低了真实调用次数？
9. 同一模型的角色争论会怎样保留原有偏差？
10. 如何验证修复过程没有因此跳过风险门？

## 自行完成的练习

1. 为独立离线任务组添加一条证据多样性规则，比较两种路由的触发率。
2. 用相同脚本输出做角色互换，观察验证状态和 Trader 的 Hold 条件。
3. 给模拟用量测试加入一次缺失 usage，并检查 A3 已占用余额。
