## 配置

- T0 是同日期的确定性 MomentumBackend。T1–T4 使用 BigModel glm-5.3-flash、温度 0、低推理、768 最大输出 Tokens、12,000 请求 UTF-8 bytes、无传输或 SDK 重试。所有模型响应逐次验证身份，统一 B2 TokenBudget。相同 Flash V3 Analyst/Trader 基础 Prompt、Pydantic 契约、市场/SEC 工具、本地传输、Verifier、风险门和有界恢复。每实例最多 8 次模型请求、1 轮工具、每轮最多 2 次调用，保留 Analyst/Trader 共享的一次结构修复额度。
- T2/T3/T4 首选 S3。现有证券范围、原文版本、时点过滤和持久 BGE-small 索引维持原顺序，两路各 50，按 Chunk ID 去重后由固定 BGE-reranker-v2-m3 一次排序，最多返回 5 个候选。仅索引 Pilot cutoff 可用的 V3 SEC、发行人新闻与公告。原金融工具范围对各组一致。若 S3 在真实模型启动前无法加载、检索范围错误、固定 Smoke 合法候选为零，或单次重排超过 8 秒，回退旧 R3 的候选 24、Top-4。更换未通过时点审计的语料不是回退方式。
- C1 通用选择器保留原金融关键词、短语、数值及邻近表头策略。每项附引用、原文定位与片段 token 区间，原文省略显式标记；单次固定检索最多 3200 实际 UTF-8 bytes。请求总预算依旧由 Provider 检查。若冻结前真实语料兼容检查无法送达，回退原交易 Agent 的前缀证据选择。
- T3/T4 分库存储相同来源的 M3，BGE-small 384 维、同股 Top-3、1800 bytes，原 R4 权重 0.65/0.25/0.10 和 30 天时间衰减。只取 20 题以外、在对应 Pilot cutoff 已独立结算的非 Pilot V3 Development 任务，用确定性 MomentumBackend 和 Reflection 生成原历史经验。运行期间固定初始库，不写入当前 Pilot Episode。历史证据 ID 不能成为当前引用。
- T4 仅加历史 D2 的原触发与预算谓词，Bull、Bear 串行独立，确定性 adjudication，无补充轮。本轮不增加“有/无 Debate”的额外 Trader 调用，记录 T3/T4 观察到的动作差并明确它不是单实例反事实。
- 预测仅打开按任务裁到 cutoff 的行情、当时已可见证据和 XBRL、独立索引和 Warm-up。当前任务不结算。只有 100 个预测终态密封后，独立命令读取公开 Development 市场前缀至 2026-08-07 结算，并核验禁止的 Holdout 和 Private 数据边界。预测保持不可覆写；HTTP 后未能匹配检查点、请求无法对账、身份/认证/时点错误时停机。任务级结构错误保留完整分母。

## 预算与筛选

B2 上限 1,000,000，全项目 15,000,000，Pilot 含 Smoke 子上限 500,000。单请求保守预留上限 13,664，实际按请求字节和输出上限预留。正式阶段开始前公开四个 Smoke 的实际费用、预留、以观测速率加一笔最大请求估计的剩余 Pilot 用量、按原协议的双倍压力估算及三种后续 60 题的费用。单题压力估算是风险边界，启动须通过观测速率估算，运行继续由每请求原子预留制约；任何硬额度不足立即停机。真实 Smoke 必须四组任务正常，T2–T4 实际送达 RAG、T3/T4 注入 M3、T4 成功运行两角色，且模型身份及项目账本一致。
