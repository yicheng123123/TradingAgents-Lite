# 后续真实模型实验协议草案

本轮执行到离线阶段。Reflection 试验与 Trader 试验需要分别授权。现有代理评测未达到排名替换与压缩提质门槛，建议先由独立评审基于历史截止可见材料标注相关性，并补充同股票有足量成熟经验的 Development 片段。只用实际结算以外的 contemporaneous evidence 审查当前任务。

## 初步 Reflection 试验

从冻结列表预选 20 个成熟 Episode，以规则反思作同题对照。冻结模型及配置、给定情境及原证据、解码、输出 schema、错误终止和人工评分标准。先评分事实与引用符合率、无依据因果、可迁移性及适用边界，再评估其对排序和实际送达的影响。记录真实生成 UTC 时间。历史模拟单独标注模拟可用时间，在线可用时间用结果实际产生的时点。

每版本一次正常请求，结构校验失败最多一次修复，传输重试为 0。缓存键基于 Episode 版本，指定单独的试验缓存；换模型或协议须冻结新试验。调用失败或进程中断的 claim 留在持久账本，等待人工审计。用户授权后使用原 TokenBudget，超出预留即停止。事实字段由代码绑定，模型只返回四条假设性过程说明。

以 4,000 请求 bytes、256 最大输出 tokens、同量推理预留及 128 协议预留计，每次最高预留 **4,640 tokens**。20 个 Episode 的 20 正常 + 最多 20 修复共 **40 次 / 185,600 tokens**。若未来对全部 100 条执行，单独估算为 **200 次 / 928,000 tokens**。这些是本地账本预留上界，执行前用实际 A2 阶段与全项目剩余预算做 preflight。

## Trader 配对试验

独立冻结 12 项合法 Development 任务与同一份历史库，再按任务配对比较 T-M0 无 Memory、T-M1 历史 M3、T-M2 经独立标签通过门槛的优化 Memory。冻结并复用 Analyst 输出、原始证据、RAG、Prompt 非 Memory 部分、工具权限、模型及解码、Debate、风险门、预算。随机化三个配置在每任务内的运行顺序、盲评输出，记录历史经验错误引用。后续才允许不同实验组维护各自的历史库。

Trader 预算只涵盖冻结 Analyst 输出后的 Trader 比较。每单元 1 正常请求 + 最多 1 格式修复，传输重试 0。按 8,000 请求 bytes、512 输出、512 推理及 128 协议预留，每次上界 **9,152 tokens**。12 × 3 × 2 为 **72 次 / 658,944 tokens**。两项小规模试验合计上限 **112 次 / 844,544 tokens**。全链路重跑 Analyst、Debate 或工具须重新计预算。

报告质量盲评、完成率、风险违规、历史误引用、经验相关性、方向准确率、策略 Alpha、真实 Token、平均和 P95 延迟及成对区间。小试验只能用来检查机制和可行性。若相关性或证据审计失败，回退到现有 M3，保留失败样本供复查。
